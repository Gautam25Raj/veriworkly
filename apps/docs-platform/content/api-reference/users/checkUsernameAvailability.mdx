title: Check Username Availability
description: >
  Reports whether a username can be claimed. Intended to drive live feedback in
  a username

  picker before `PUT /users/me/username` is called.


  This route carries **no API-key scope gate**, unlike the rest of the Users
  module — but it is

  still not anonymous, so it needs an API key or a whitelisted first-party
  origin.


  The path segment is normalised the same way the update endpoint normalises it,
  and

  `normalizedUsername` echoes back the value that would actually be stored. A
  `200` with

  `available: false` is the normal negative answer — an unavailable name is not
  an error.
