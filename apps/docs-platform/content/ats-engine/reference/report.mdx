## `AtsCategoryScore`

Per-category rollup of the deterministic rules. `lost` is the sum of the score impacts the category actually cost, `possible` the worst case it could have cost, so `score` is the percentage of that category the resume kept. Exposing the rollup is deliberately safe: it is an aggregate of numbers the full report already returns per rule, and it tells an anonymous caller _where_ the problem is without handing over the rule-by-rule answer key.

<TypeTable
  type={{

    passed: { type: "number", required: true },
    total: { type: "number", required: true },
    lost: { type: "number", required: true },
    possible: { type: "number", required: true },
  }}
/>

## `AtsAdvice`

Something worth knowing that is not scored: about the file (its name, size, a password, tracked changes or comments left in), about details that can invite age bias where the region pack says so, and about a target ATS the caller named. Never part of the readiness score, the categories, the failed checks or the fixes. The text comes from the policy (`advice`).

## `AtsParsedResume`

Returned to the caller as well as scored, because showing the candidate the rows we recovered is more useful than any number: an empty employer or a missing date range is a column the hiring team's filter cannot match, and seeing it is what makes that concrete.

## `AtsParsedLanguage`

One language the candidate speaks. `language` as written ("Deutsch", "English"), `level` the words that state the level as written ("native", "verhandlungssicher, C1"; empty when none), and `cefr` that level on the CEFR scale, or null when no level word the policy knows was given.
